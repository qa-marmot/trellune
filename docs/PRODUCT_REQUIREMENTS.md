# Trellune 製品要件

最終更新: 2026-08-13
対象: 365日間の英語学習用スマートフォンPWA

## 1. 製品の目的

Trelluneは、日本語母語の英語学習者が、毎日の必須学習（Core）と任意学習（Boost）を区別しながら365日間継続するための個人用学習システムである。学習内容、復習、進捗、ChatGPTで実施した会話結果を端末内で管理し、本人が承認した場合のみD1と同期する。

365日後の目標は次のとおり。

- 身近な話題や一般的な論点について15〜25分会話する。
- 既習文法を統合し、B2入口へ挑戦する会話課題で使用する。
- 600〜800語と頻出定型表現150個を能動的に使用する。
- 過去・現在・未来を説明する。
- 聞き返し、言い換え、追加質問で会話を継続する。

## 2. 対象利用者と利用環境

- 主利用者は日本語母語の英語初心者1名である。
- 主端末はスマートフォン。キーボード、画面読み上げ、拡大表示にも対応する。
- 不安定な通信や完全オフラインでも、事前に取得済みの教材とローカルデータを利用できる。
- ChatGPTは別アプリまたは別タブで人間が操作する。Trelluneとの連携は、プロンプトと検証済みJSONのコピー＆ペーストに限定する。

## 3. 製品境界

### Trelluneが行うこと

- 365日カリキュラム、今日のCore、文法教材と問題、単語、定型表現を提示する。
- Day 1〜365のlearner supportを日本語または英語で表示する。言語変更は端末内の
  presentation設定であり、学習進捗・stable ID・同期・backupを変更しない。
- 間隔反復、間違いノート、履歴、進捗分析を管理する。
- ChatGPT向けプロンプトを生成し、利用者が貼り付けたJSONを検証・プレビュー・取り込みする。
- IndexedDBをローカルの即時応答用ストアとして利用し、D1との同期、バックアップ、復元を提供する。
- PWAとしてインストール可能で、オフライン状態を明示する。

### ChatGPTが行うこと

- Voice英会話、文法指導、表現修正、発音フィードバック、日次・週次評価を行う。
- Trelluneの公開スキーマに適合するセッションJSONを生成する。

### 行わないこと

- OpenAI API、Realtime API、Agents SDK、Workers AI、その他のAI APIを呼び出さない。
- ChatGPTへの自動投稿、非公開API利用、ブラウザ自動操作を行わない。
- 音声を保存しない。アプリ内AIチャット・AI Voice、広告、課金、SNS、ストア公開を実装しない。

## 4. 用語と不変条件

- **学習日**: 利用者の設定タイムゾーンにおける暦日。初期値は `Asia/Tokyo`。
- **Core**: 期限が来た必須復習、当日の文法課題、Core Voice結果JSON取込の組み合わせ。
- **Core完了**: 同一学習日の必須復習と文法課題が完了し、有効なCore Voiceセッションが1件以上取り込まれた状態。
- **Boost**: Core完了後に選べる任意学習。未実施でも失敗や連続日数の中断にならない。
- **previewed**: 未来の教材へ触れたが、予定日のCore完了や正式習得には数えない状態。
- **新規項目**: その学習日に初めて獲得対象として登録される単語・定型表現・先取り文法。
- **必須復習**: 当日開始時または最後の再計算時点で期限が到来しているCore対象カード。同期で遅れて到着した履歴を考慮して決定的に再計算する。

以下はUI、ドメイン、永続化、同期の全層で守る。

1. Boostは未来の日のCoreを完了させない。
2. `previewed` は予定日の正式なCore学習まで保持する。
3. 1学習日あたり、新規単語8語、新規定型表現3個、先取り文法1テーマを超えて登録しない。
4. 上限到達後も復習と会話は続行できる。
5. Core完了だけが連続学習日数を増やす。
6. 外部入力はZodで検証後にのみドメイン・永続化へ渡す。
7. 不正JSONを推測補完して保存せず、貼り付け原文を画面から失わせない。

## 5. 機能要件

### PR-ONB: 初期設定とベースライン

- **PR-ONB-01** 初回起動で、利用目的、データ保存先、オフライン動作、ChatGPT連携方式、音声非保存を日本語で説明する。
- **PR-ONB-02** タイムゾーン、学習開始日、1日の目安時間、自己評価を入力し、確認後にプロフィールを作成する。
- **PR-ONB-03** ベースライン評価用プロンプトを生成・コピーし、結果JSONを通常の安全な取込フローで受け付ける。
- **PR-ONB-04** ベースラインをスキップしても利用開始でき、後から実施できる。

### PR-TDY: TodayとCore

- **PR-TDY-01** Todayに学習日、オフライン/同期状態、Core進捗、各必須タスク、Boost入口を表示する。
- **PR-TDY-02** 必須復習をカード単位で提示し、回答評価に基づいて次回期限を更新する。
- **PR-TDY-03** 当日の文法説明、例、課題、フィードバックを提供する。
- **PR-TDY-04** Core Voice用プロンプトを当日の文法、復習対象、会話目標から生成する。
- **PR-TDY-05** Core完了判定をサーバー時刻だけに依存させず、学習日と完了イベントから再現可能に算出する。
- **PR-TDY-06** 未完了の理由を「復習」「文法」「Voice取込」に分けて表示する。

### PR-CUR: カリキュラムと教材

- **PR-CUR-01** 365日分のStage、Unit、日、週、テーマ、文法、会話目標を閲覧できる。Day 1〜270は既存内容・ID・順番を維持する。
- **PR-CUR-02** 今日、完了、未完了、ロック中、previewedを色だけに依存せず区別する。
- **PR-CUR-03** 文法、単語、定型表現の一覧・詳細・検索・状態絞り込みを提供する。
- **PR-CUR-04** Coreだけで全カリキュラムと目標語彙・表現へ到達できる構成にする。

### PR-REV: 間隔反復と間違い

- **PR-REV-01** 期限、失敗履歴、難易度に基づき復習順を決定する。同じ入力から同じ結果を得られる。
- **PR-REV-02** 回答評価と次回予定を保存し、履歴から再計算可能にする。
- **PR-REV-03** 間違いを分類、回数、最後の発生、関連項目とともに表示する。
- **PR-REV-04** 同種のミスが3回以上ならWeakness Attackを優先提案する。

### PR-BST: Boost

- **PR-BST-01** Core完了後、5/15/30/60分を選択できる。
- **PR-BST-02** Review Rescue、Speaking Sprint、Grammar Deep Dive、Scenario Challenge、Weakness Attack、Next Lesson Preview、Free Talkを選択できる。
- **PR-BST-03** 期限切れ復習が多い場合はReview Rescueを優先提案し、同じミスが3回以上ならWeakness Attackを優先提案する。提案理由を表示し、別モードも選択可能にする。
- **PR-BST-04** 時間、モード、現在の弱点、残り新規枠からプロンプトを生成する。
- **PR-BST-05** Boost結果の新規項目を上限内だけ取り込み、超過時は取込全体を無言で切り捨てず、項目ごとの修正可能なエラーを示す。
- **PR-BST-06** Next Lesson Previewの対象を`previewed`として登録し、未来のCore状態・連続日数を変更しない。

### PR-CGB: ChatGPT Bridge

- **PR-CGB-01** Core Voice、各Boost時間、Study Mode、週次評価の用途別に、バージョン付き契約を含むプロンプトを生成する。
- **PR-CGB-02** ボタン操作でプロンプトをコピーし、コピー成功・失敗をテキストで通知する。
- **PR-CGB-03** 貼り付け欄への直接入力と、利用者操作によるクリップボード読込を提供する。権限拒否時も直接入力を維持する。
- **PR-CGB-04** 生JSONまたはMarkdownコードブロック内の単一JSONを抽出する。単一コードブロックの前後にある説明文は警告付きで無視してよいが原文には残す。複数JSON候補、候補の曖昧さ、構文不正は利用者に選択・修正を求める。
- **PR-CGB-05** JSON Schema/Zod、契約バージョン、Core/Boost種別、日付、ID、上限、参照整合性を検証する。
- **PR-CGB-06** 保存前に変更内容、警告、エラー、Core/Boost判定をプレビューする。
- **PR-CGB-07** 修正はコピー上で行い、貼り付け原文をセッション中保持する。原文を学習データやログへ永続化しない。
- **PR-CGB-08** 安定した外部セッションIDと内容ハッシュで二重取込を防ぎ、同一内容の再取込は副作用なく既存記録を案内する。
- **PR-CGB-09** 取込は原子的に行う。検証または永続化の一部が失敗した場合、Core完了、カード、上限カウンターを部分更新しない。

### PR-HIS: 履歴と分析

- **PR-HIS-01** セッション一覧・詳細に日時、種別、モード、学習時間、結果、生成カードを表示する。
- **PR-HIS-02** Core完了日、連続日数、復習状況、語彙・表現・文法の進捗、弱点推移を表示する。
- **PR-HIS-03** 集計値はイベント/保存記録から再構築でき、BoostをCoreとして集計しない。

### PR-OFF: IndexedDB、同期、バックアップ

- **PR-OFF-01** アプリシェル、取得済み教材、学習操作をオフラインで利用できる。通信必須操作は理由と再試行方法を示す。
- **PR-OFF-02** ローカル変更を一意な操作ID、作成時刻、端末ID、スキーマ版とともにキューへ積む。
- **PR-OFF-03** 同期APIは冪等で、再送・順不同・中断から回復する。競合は文書化された規則で解決し、Core/Boost不変条件を再検証する。
- **PR-OFF-04** 同期中、完了、未同期件数、競合、最終成功時刻を表示する。
- **PR-OFF-05** バックアップを書き出す前に内容と機微性を説明する。バックアップはバージョン付き・検証可能で、音声・秘密情報・貼り付け原文を含めない。
- **PR-OFF-06** 復元は検証→影響プレビュー→明示確認→原子的適用の順で行い、失敗時に既存データを保持する。

### PR-API: Worker APIと認証境界

- **PR-API-01** Hono APIは `/api` 配下に置き、入力・パス・クエリ・応答境界をZodで検証する。
- **PR-API-02** D1アクセスはバインドパラメーターを使用し、文字列連結SQLを使用しない。
- **PR-API-03** DB変更は番号付きマイグレーションと後方互換処理を伴う。
- **PR-API-04** 本番と開発のAPIはCloudflare Accessの背後に置き、認証済み本人のデータだけを扱う。クライアント提供の利用者IDを信頼しない。
- **PR-API-05** エラー応答は安定したコードと相関IDを持ち、秘密情報・学習本文・スタックトレースを返さない。

### PR-SET: 設定とデータ管理

- **PR-SET-01** タイムゾーン、表示、学習通知相当のローカル設定、同期設定を変更できる。
- **PR-SET-02** データ削除は対象と不可逆性を説明し、再確認を要求する。本番データ操作は人間の承認なしに実行しない。
- **PR-SET-03** アプリ版、スキーマ版、契約版、接続状態、診断情報を表示する。診断情報をコピーする際は個人データを除く。

## 6. 非機能要件

### NFR-A11Y アクセシビリティ

- WCAG 2.2 AAを目標とし、主要フローにaxe自動検査と手動キーボード/画面読み上げ検査を実施する。
- すべての操作をキーボードで完了でき、フォーカスが可視で、モーダル内に適切に留まり、終了後に起点へ戻る。
- 入力には可視ラベル、説明、フィールド単位のエラー関連付けを持たせる。状態を色、位置、音だけで伝えない。
- 200%拡大、320 CSS px幅、縦横表示で主要操作を失わない。タップ対象は原則44×44 CSS px以上とする。
- 動きは`prefers-reduced-motion`を尊重し、時間制限を設けない。

### NFR-PERF 性能

- 低速モバイル回線でもアプリシェルを優先表示し、長い教材・履歴はページングまたは仮想化する。
- 同じ操作の多重送信をUIとAPIの双方で抑止する。
- 性能目標は実機計測で、主要ルートのLCP 2.5秒以下、INP 200ms以下、CLS 0.1以下（75パーセンタイル）を目標とする。未達はリリースレポートに記録する。

### NFR-SEC セキュリティ・プライバシー

- 音声、秘密情報、貼り付け原文、ローカルDB、実学習バックアップをGit・遠隔測定・通常ログへ保存しない。
- 最小限の個人データだけを保存し、第三者広告・分析SaaSを使用しない。
- CSP、セキュアヘッダー、同一オリジン、Access、入力検証を多層で適用する。
- 本番デプロイ、リモートD1作成/移行、DNS、Access、本番データ変更には明示的な人間の承認を必要とする。

### NFR-REL 信頼性・保守性

- TypeScript strict、lint、format check、unit/integration、Playwright、buildをCIで再現する。
- 保存形式、JSON契約、API、DBに版を持たせ、未知の将来版を拒否する。
- 更新前のデータを後方互換に読み、破壊的DB変更は行わない。
- P0/P1が残るGateは完了にしない。最大5回で解消しない場合は停止し、選択肢を記録する。

## 7. 成功指標

- Core開始率、Core完了率、週あたりCore完了日数、Day 90/180到達率。
- 期限切れ復習件数と解消時間、同一ミスの再発率。
- 能動語彙600〜800語、定型表現150個への進捗。
- 10分会話評価、時制使用、会話修復表現の週次評価推移。
- JSON取込成功率、修正率、二重取込防止件数、同期失敗からの回復率。

指標は利用者本人への表示に使い、外部分析サービスへ送信しない。

## 8. リリース境界

- ローカル完成: 全主要フロー、オフライン、バックアップ復元、D1ローカルを検証済み。
- 開発環境準備: `dev.app.example`、D1 `trellune-dev`、Access設定手順が揃い、人間の承認待ち。
- 本番準備: `app.example`、D1 `trellune-prod`、バックアップ/ロールバック/監視/障害対応が検証され、人間の承認待ち。
- GitHub remote作成、push、Cloudflareログイン、リモート資源作成、デプロイ、DNS/Access変更は本成果物の自動実行範囲外である。

詳細な判定は[ACCEPTANCE_CRITERIA.md](./ACCEPTANCE_CRITERIA.md)を正とする。
