# 受入基準

最終更新: 2026-08-06

## 1. 判定方法

各項目は、記載された証拠が保存され、期待結果がすべて成立したときだけPassとする。機能が存在するだけ、手動で一度動いた、またはテストが未実行の場合はPassにしない。

- **P0**: データ消失、認証回避、秘密漏えい、Core/Boost不変条件の広範な破壊、起動不能。
- **P1**: 主要フロー完遂不能、上限超過、二重取込、同期不整合、主要アクセシビリティ障壁。
- **P2**: 迂回可能な機能不具合、限定的な互換性・操作性問題。
- **P3**: 表記、軽微な視覚差、改善提案。

P0/P1が1件でもOpenなら該当GateとリリースをFailとする。Skippedは理由、リスク、再実行条件、承認者を記録しない限りFailとして扱う。

## 3. シナリオ別受入基準

### AC-ONB 初期設定

1. 新規プロファイルで起動すると、個人用・ローカル優先・音声非保存・コピー＆ペースト連携の説明が表示される。
2. 必須項目の空、型不正、範囲外値はフィールドに関連付いた日本語エラーとなり、保存されない。
3. `Asia/Tokyo`を選択して確認するとプロフィールが1件作られ、再読込後もTodayへ進む。
4. ベースラインをスキップしてもTodayを利用でき、設定または専用画面から再開できる。
5. ベースラインJSONは通常取込と同じプレビュー・検証・重複防止を通る。

### AC-CORE Core完了と連続日数

次の表を自動テストで全組み合わせ検証する。

| 必須復習 | 文法課題 | 有効Core Voice取込 | Core完了 | 連続日数増加 |
| -------- | -------- | ------------------ | -------- | ------------ |
| 未完了   | 未完了   | なし               | しない   | しない       |
| 未完了   | 未完了   | あり               | しない   | しない       |
| 未完了   | 完了     | なし               | しない   | しない       |
| 未完了   | 完了     | あり               | しない   | しない       |
| 完了     | 未完了   | なし               | しない   | しない       |
| 完了     | 未完了   | あり               | しない   | しない       |
| 完了     | 完了     | なし               | しない   | しない       |
| 完了     | 完了     | あり               | する     | する         |

追加条件:

1. Core完了イベントを再送しても完了数と連続日数は増えない。
2. 23:59と翌日00:01（設定タイムゾーン）、夏時間を持つ任意タイムゾーン、端末時計変更で学習日境界が決定的である。
3. オフラインで3要素を完了し再起動しても状態を保持し、同期後に同じCore日となる。
4. 未完了理由は各要素に対応し、色だけで区別しない。
5. 必須復習0件の日は復習要件を自動的に満たすが、文法とVoiceは必要である。
6. 誤答評価ごとの次回期限が仕様どおりで、履歴から同じ期限を再計算できる。

### AC-CUR カリキュラムと教材

1. 365日が連番で存在し、全日がStage・Unit・週・テーマ・文法・会話目標を持つ。リリース済みDay 1〜270はdeep parityを保つ。
2. Foundationは既存語彙600〜800語・定型表現150個の到達設計を保ち、Independentは原則4〜6語、Fluencyは3〜5語、両Stageとも1〜3表現で日次上限を超えない。
3. 日状態の今日/完了/未完了/ロック/previewedをテキストまたはアイコン名で識別できる。
4. 直接URL、戻る/進む、再読込で選択中教材を失わない。
5. 検索0件、未取得オフライン、長い一覧でも回復手段を示す。

### AC-BOOST Boost境界と提案

1. Core未完了ではBoost入口に未完了理由を示し、未来Coreを完了できる操作を提供しない。
2. Core完了後、4時間枠×7モードを選べ、プロンプトに選択値と契約版が含まれる。
3. 期限切れ復習が仕様閾値以上ならReview Rescue、同一分類ミス3回以上ならWeakness Attackが優先表示され、理由を読み上げ可能である。両方成立時の優先規則は固定されテストされる。
4. Boost未実施の日も失敗表示や連続日数減少がない。
5. Next Lesson Preview後、未来日の文法は`previewed`、未来Coreは未完了、連続日数は不変である。予定日のCore開始後に通常遷移する。
6. 上限到達後も既存カード復習、会話プロンプト生成、結果履歴保存ができる。

### AC-LIMIT 新規項目上限

各ケースはローカル、API、オフライン同期競合の3経路で実行する。

| 当日既存     | 取込要求 | 期待結果                                |
| ------------ | -------- | --------------------------------------- |
| 単語7        | 単語1    | 8件目を許可                             |
| 単語8        | 単語1    | 新規登録を拒否し修正案内、既存8件を維持 |
| 表現2        | 表現1    | 3件目を許可                             |
| 表現3        | 表現1    | 新規登録を拒否し修正案内                |
| preview文法0 | 1        | `previewed`で許可                       |
| preview文法1 | 1        | 新規登録を拒否し修正案内                |

さらに、同一項目の再登場は新規数を増やさず、Unicode正規化・大文字小文字・前後空白に関する同一性規則を固定する。2端末がオフラインで上限内まで追加し、統合すると超過する場合、同期は全項目を黙って受理せず、決定的な競合結果と利用者向け解決画面を返す。

### AC-BRIDGE プロンプトとJSON取込

1. Core、5/15/30/60分Boost、Study Mode、週次評価の各プロンプトを生成・コピーできる。
2. Clipboard API成功、権限拒否、非対応をテストし、後二者でも貼り付け欄を操作できる。
3. 生JSON、`json`コードフェンス、BOM/前後空白を受理する。単一JSONコードフェンスの前後に説明文がある場合は警告付きで抽出し、原文を保持する。複数JSON候補、切れたJSON、配列/オブジェクト違い、巨大入力、未知契約版は保存前に拒否する。
4. 必須フィールド、列挙値、日付、UUID/ID、数値範囲、Core/Boost整合、参照ID、上限をZodで検証する。
5. エラーはJSONパス、理由、修正方法を示し、貼り付け原文を画面内に保持する。原文はリロード後の学習データ、ログ、D1に残らない。
6. プレビューに作成・更新・無変更、生成カード、previewed、Core判定、警告を表示し、明示的な「取り込む」までは永続化しない。
7. 同じ外部IDと同じ内容、異なる外部IDと同じ内容、同じ外部IDと異なる内容をテストする。最初の2つは二重副作用を防ぎ、最後は衝突として拒否する。
8. 永続化途中に例外を注入した場合、セッション、カード、ミス、日次上限、Core完了のいずれも部分更新されない。再試行は1回だけ反映される。
9. Core JSONをBoostへ、Boost JSONをCoreへ誤分類できず、手動修正後もスキーマと不変条件を再検証する。

### AC-HISTORY 履歴と分析

1. Core/Boost/評価セッションを種別、日付、モードで絞り込み、詳細へ移動できる。
2. 履歴から分析DBを空にして再構築した結果が、保存済み集計と一致する。
3. Boostのみの日はCore完了数・連続日数に入らない。previewedは正式習得数に入らない。
4. データ0件、部分同期、削除済み参照があっても画面がクラッシュせず、状態を説明する。

### AC-OFFLINE オフラインと同期

1. 一度オンラインで主要画面を開いた後、ネットワークを切断してToday、取得済み教材、復習、文法、プロンプト生成、JSON取込、履歴を利用できる。
2. オフライン操作は即時にローカル反映され、未同期件数が増える。再起動後もキューを保持する。
3. 同一操作を5回再送、応答喪失後再送、順不同送信、同期中切断を行っても最終状態は1回適用と一致する。
4. 401/403ではログイン案内、409では競合解決、429/5xx/通信断では指数バックオフと手動再試行を示す。無限高速再試行しない。
5. service worker更新は作業中データを失わず、更新可能であることを通知して利用者の再読込操作を待つ。
6. 未取得URLをオフラインで開くと専用説明と取得済み画面への導線を表示する。

### AC-BACKUP バックアップと復元

1. 書き出し前に含まれるデータと保管上の注意を表示する。
2. バックアップに形式版、作成日時、整合性情報があり、音声、Access資格情報、秘密、貼り付け原文を含まない。
3. 正常バックアップ、旧対応版、未知将来版、改ざん、切断、巨大ファイル、上限違反を検証する。
4. 復元プレビューが追加/更新/競合件数を示し、確認前は既存データを変更しない。
5. 適用途中の失敗で既存データが保持される。成功後は再起動・集計再構築・同期を経ても一致する。

### AC-API API・D1・Access

1. すべてのAPI入力をZod検証し、不正時は安定した4xxコードを返す。未知フィールドの扱いを契約で統一する。
2. repositoryの全SQLがbindを使用し、静的レビューで文字列連結SQLが0件である。
3. 空DBに番号順でmigrationを適用でき、旧版fixtureを最新版へ上げてもデータと不変条件を保持する。同じmigrationの再実行手順が安全である。
4. 本番相当ではAccess情報なし/無効/別利用者を拒否し、クライアントの利用者ID差し替えで他データを取得できない。
5. APIエラーとログにJSON本文、学習本文、メール、token、stackが含まれず、相関IDで追跡できる。

### AC-A11Y アクセシビリティ

1. onboarding、Today、復習、文法、Voice準備、取込、Boost、履歴、バックアップ、設定に重大/深刻なaxe違反が0件である。
2. マウスなしで全主要フローを完遂し、論理的なフォーカス順、可視フォーカス、スキップリンク、ダイアログのフォーカス復帰を確認する。
3. NVDA + ChromeまたはEdgeで見出し、ランドマーク、フォーム名、エラー、進捗、同期通知、取込結果が理解できる。
4. 320×568 CSS px、200%ズーム、400%テキスト拡大相当で双方向スクロールを主要コンテンツに要求せず、操作が隠れない。
5. 明色/暗色の通常・hover・focus・disabled・errorでWCAG AAコントラストを満たす。
6. `prefers-reduced-motion`で非必須アニメーションが停止し、状態変化を動きだけで伝えない。

### AC-PWA PWAと互換性

1. manifestに名称、短縮名、start URL、scope、display、theme/background、192/512アイコンがあり、同一オリジンで取得できる。
2. production buildをHTTPS相当で配信し、service worker登録、更新、オフラインfallbackを確認する。
3. 最新2版のChrome/Edge、現行Safari iOS、Android Chromeで主要フローをスモークする。未対応機能にはfallbackがある。
4. install可能性を満たさない環境でも通常のWebアプリとして利用できる。

### AC-PRIVACY セキュリティ・プライバシー

1. リポジトリとbuild artifactに秘密、実学習データ、音声、ローカルD1/IndexedDB dumpがない。
2. 通常ログ、エラーログ、診断コピーに貼り付けJSON、プロンプト全文、学習本文、メール、tokenがない。
3. CSP、`X-Content-Type-Options`、適切な`Referrer-Policy`、`Permissions-Policy`、frame制御を確認する。
4. 依存関係監査の重大/高リスクを評価し、悪用可能なP0/P1が0件である。
5. データ削除は対象明示と二段階確認を持ち、取消不能操作は人間承認なしに自動実行されない。

## 4. CI・リリース受入

クリーンcheckout、Node 22、package.json指定pnpmで次を成功させる。

```text
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install --with-deps chromium
pnpm playwright test
```

追加のリリース条件:

- developmentとproductionの設定・D1・ホスト名が分離されている。
- ローカルmigration、seed、バックアップ、復元、ロールバック手順が第三者PCで再現されている。
- P0/P1 Openが0件で、既知P2/P3に影響・回避策・担当Gateがある。
- 開発/本番デプロイ、remote作成/push、D1/DNS/Access変更は明示承認まで未実行である。
- リリース報告にcommit、build、migration版、テスト結果、承認記録、ロールバック基準がある。
