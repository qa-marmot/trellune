# プライバシー

最終更新: 2026-08-06

## 1. 方針

Trelluneは個人用・ローカル優先の学習PWAである。学習に必要な最小限のデータだけを扱い、第三者広告、行動分析SaaS、AI APIへ送信しない。会話AIとの連携は、利用者自身が別画面で行うコピー＆ペーストだけである。

## 2. データ一覧

| データ         | 例                             | 保存先                  | 目的               | 保持/削除             |
| -------------- | ------------------------------ | ----------------------- | ------------------ | --------------------- |
| 学習設定       | タイムゾーン、開始日、目安時間 | IndexedDB、同期時D1     | 学習日と表示の決定 | 設定から削除          |
| 学習状態       | Core要素、previewed、期限      | IndexedDB、同期時D1     | 進捗・復習         | データ削除まで        |
| 学習履歴       | 回答評価、セッション、ミス     | IndexedDB、同期時D1     | 履歴・分析・再計算 | データ削除まで        |
| 教材           | 文法、単語、表現、カリキュラム | app/IndexedDB、必要時D1 | オフライン教材     | app更新/削除まで      |
| 同期メタデータ | 操作ID、端末ID、版、ack        | IndexedDB、D1           | 冪等同期           | 同期/保守方針に従う   |
| 認証主体       | Accessで検証した識別子         | Worker/D1の分離key      | 本人データの分離   | Access/データ削除まで |
| バックアップ   | 上記のversioned export         | 利用者が選ぶ端末保存先  | 手動保全・復元     | 利用者が管理          |

## 3. 保存しないデータ

- 音声録音、音声ファイル、音声の生体特徴。
- ChatGPTの資格情報、cookie、token、非公開API情報。
- 貼り付けたJSONの原文。取込画面のセッション内で修正のため保持しても、学習DB、D1、通常ログへ永続化しない。
- プロンプト全文や学習回答本文を通常の運用ログ・分析イベントに記録しない。
- Cloudflare Accessのtoken、秘密、`.dev.vars`、ローカルD1/IndexedDB、実バックアップをGitへ追加しない。

## 4. ChatGPTとのデータ移動

1. Trelluneは、その日の目標と必要な学習文脈を含むプロンプトを画面に生成する。
2. 利用者が内容を確認し、自分でコピーしてChatGPTへ貼り付ける。
3. 利用者がChatGPTのデータ取扱い設定を自分で管理する。
4. 結果JSONも利用者が確認してTrelluneへ貼り付ける。
5. TrelluneはZod検証と取込プレビュー後、利用者が確定した構造化項目だけを保存する。

TrelluneからChatGPTへ自動送信しない。クリップボードはボタンを押したときだけ読み、権限拒否を尊重する。

## 5. ローカル、同期、バックアップ

- IndexedDBは端末のブラウザプロファイル内にあり、同じOS利用者やブラウザ拡張から完全に隔離されるとは限らない。共有端末ではOS/ブラウザプロファイルを分ける。
- D1同期は明示された同期機能のために使い、Cloudflare Accessで本人を確認する。クライアント提供の利用者IDを認可根拠にしない。
- 同期通信はHTTPSに限定する。開発と本番のD1を混在させない。
- バックアップは暗号化されない可能性があるため、生成前に内容と安全な保管を説明する。共有フォルダーや公開クラウドへ置かないよう案内する。
- バックアップへ音声、秘密、token、貼り付け原文を含めない。復元前に形式、版、整合性、上限を検証する。

## 6. ログと診断

許可するログは、時刻、相関ID、route、結果コード、処理時間、件数、schema/contract版など、問題解決に必要な最小メタデータである。

次をログへ出さない。

- request/response body、貼り付けJSON、プロンプト、回答、例文、ミス本文。
- メール、Access JWT/header、cookie、秘密、backup内容。
- stack traceを利用者向けresponseへ返さない。サーバーログでも入力値の埋込みを避ける。

診断情報コピーは保存前にプレビュー可能とし、個人データをredactする。Playwright trace、screenshot、CI artifactにも実データを使わない。

## 7. 利用者の制御

- 保存中のデータ種類、ローカル/同期状態、最終同期時刻を設定画面で確認できる。
- バックアップを書き出し、検証・プレビューを経て復元できる。
- 設定画面の端末削除は、プロフィール、設定、学習状態、履歴、復習、未送信操作を対象として明示し、同期済みD1データを削除しない。
- 端末削除はバックアップ推奨と不可逆性を表示し、確認チェックと指定文言入力の二段階確認がそろうまで実行できない。削除後はD1から自動再取得せず、削除開始前から通信中だった同期応答も端末へ再適用しない。
- 本番D1の削除や破壊的変更は自動実行せず、人間の明示承認と運用記録を要求する。

## 8. セキュリティ境界と残存リスク

- Cloudflare Accessは入口保護であり、アプリ側の主体検証、入力検証、最小権限、bind SQLの代替ではない。
- service worker/cacheには秘密を入れない。認証済みAPI応答を共有cacheへ保存しない。
- XSSはローカル学習データも漏えいさせるため、貼り付け内容をHTMLとして描画せず、CSPとReactの既定エスケープを維持する。
- 端末紛失、マルウェア、悪意ある拡張、利用者がChatGPTへ貼る内容はTrelluneだけでは完全に制御できない。OS暗号化、画面ロック、専用ブラウザプロファイル、貼り付け前確認を推奨する。

## 9. 開発・レビュー時のチェック

- `git status`と履歴で実データ、音声、DB、`.dev.vars`、backupが追跡されていない。
- fixtureは架空データのみで、メール/token形式も明確なテスト値を使う。
- 新しい外部通信、依存SaaS、ログ項目、保存フィールドを追加する変更は、この文書、要件、schema、削除/backup経路、テストを同時に更新する。
- P0/P1のプライバシーfindingがあるGateを完了にしない。
