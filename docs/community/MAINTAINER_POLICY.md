# Lightweight maintainer policy

Trellune aims to acknowledge Issues and pull requests within roughly 48–72
hours when possible. This is a goal, not a service-level agreement.

- **Issues** are for specific, reproducible work or defects.
- **Discussions** are for questions, ideas, learning stories, and early feedback.
- **Pull requests** should stay small, explain learner impact and compatibility,
  and include focused validation.
- **Sensitive reports** must follow [SECURITY.md](../../SECURITY.md), never a
  public Issue or Discussion.

Community help is especially valuable for documentation, UI localization,
provider verification, physical-device QA, accessibility, and curriculum review.
The maintainer may defer a feature that weakens local-first privacy, stable
learning data, or the Core/Boost boundary.
